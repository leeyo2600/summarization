# 법령 의견조회 요약 웹앱

주요내용을 중심으로 기존 제도에서 달라지는 점을 요약하고 엑셀로 출력하는 로컬 웹앱입니다.
이유·본문·대비표는 부족한 정보를 보완하는 데 사용합니다.

## 실행 (Windows / Python 3.12)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-web.txt
.\.venv\Scripts\python.exe start_web.py
```

HWPX·공문 PDF만 사용할 때는 Java가 필요하지 않습니다. HWP를 사용하려면 Java 17 이상을 설치하고 다음을 실행하세요.

```powershell
.\.venv\Scripts\python.exe tools/build_converter.py
```

화면에서 API 키를 입력합니다. `webapp/api.py`의 `MODEL='gpt-6-luna'`는 주요내용 요약용, `DEPARTMENT_MODEL='gpt-6-sol'`은 비고 추천용입니다. 두 모델에 접근할 수 있는 API 계정이 필요합니다.
Chat Completions의 JSON 응답을 사용하며, 요약은 `reasoning_effort=none`, 비고는 `medium`입니다. 컨텍스트 한도는 1,050,000토큰, 앱 출력 예산은 8,192토큰입니다. 입력 크기는 UTF-8 바이트로 보수적으로 검사하고 한도 초과 시 원문을 자르지 않고 오류를 표시합니다.
주요내용은 Luna로 요약하고, 법령명·소관기관·기한은 기존 원문 추출 및 표시 방식을 유지합니다. 비고만 Sol로 판정하며 로컬 임베딩 모델은 사용하지 않습니다. 처리기록에는 요약과 비고의 모델·API 사용 내역을 구분해 저장합니다.

## 현재 웹 전체 처리: Sol 단독 추천

`python start_web.py`로 재시작한 뒤 OpenAI API 키와 국가법령정보센터 OC를 입력하고 소관부서 추천을 켠 상태에서 전체 ZIP을 올리세요. 일반 **제·개정사항 요약 시작** 버튼이 모든 법령 행을 처리하며, 두 행 제한은 별도 실험 버튼에만 적용됩니다.

국가법령정보센터의 현행 직제 시행규칙을 작업마다 조회하고, 부서별 전체 업무분장과 법령명·요약 주요내용을 Sol에 보내 의견 검토에 관련된 부서 하나 또는 `없음`을 받습니다. 직접 소관 부서만으로 제한하지 않지만 기능·제도가 실질적으로 유사하다는 업무 근거가 필요합니다. 임베딩·threshold는 사용하지 않습니다. 근거 업무 ID를 검증하며 선택 이유·근거는 처리기록에 저장합니다. 오류는 `없음`으로 위장하지 않고 빈칸과 오류 목록에 표시합니다.

기존 요약을 유지하려면 결과를 불러온 뒤 **gpt-6-sol로 비고 재처리 · 전체 또는 빈칸**에서 **기존 “없음”을 포함해 모든 행의 비고를 다시 판정**을 체크하고 실행하세요. 새 엑셀을 저장하며 원본 파일은 보존합니다. 전체 업무분장을 행마다 전송하므로 API 비용과 처리 시간이 발생합니다.

현재 운영 코드는 `webapp/gpt_departments.py`이며, 공통 프롬프트는 `webapp/gpt_department_experiment.py`의 `PROMPT`입니다. 아래 임베딩 안내는 이전 방식의 진단 도구용이며 현재 웹 실행에는 적용되지 않습니다.

## 이전 임베딩 방식 준비 (진단 도구용)

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-departments.txt
```

화면에서 '행정안전부 소관부서 추천'을 켜고 국가법령정보센터 공동활용 API에서 승인받은 OC를 입력하세요.
OC와 OpenAI 키는 파일에 저장하지 않습니다. 추천을 해제하면 요약만 실행하고 비고는 빈칸입니다.
화면의 **임베딩 모델 미리 다운로드** 버튼으로 API 키·OC 없이 모델 파일부터 준비할 수 있습니다.
선택 항목인 **Hugging Face 토큰**에 읽기 토큰을 입력하면 미리 다운로드와 요약 시작 시 모델 준비 모두에 사용합니다. 입력이 없으면 `HF_TOKEN` 환경변수 또는 기존 Hugging Face 로그인 토큰을 사용하며, 아무 토큰도 없으면 공개 다운로드합니다. 앱은 토큰을 설정·완료 기록·처리 결과 파일에 저장하지 않습니다. 토큰은 요청 제한 완화에 도움이 될 수 있지만 회선 속도를 보장하지 않습니다.
다운로드 중에는 회전 로딩 표시와 현재 단계를 보여줍니다. 실패하면 **다시 시도**를 누르세요.
다운로드 단계에서는 경과 시간, 파일 준비 용량/전체 용량과 진행률, 실제 누적 전송량·평균 전송 속도, 예상 남은 시간을 표시합니다.
캐시 재사용과 압축 전송 때문에 준비된 파일 용량과 네트워크 전송량은 다를 수 있습니다. 남은 시간은 최근 파일 준비 속도로 추정하며, 측정값이 부족하거나 진행이 멈추면 '계산 중'으로 표시합니다. 다운로드 후 파일 검사·메모리 로딩 시간은 추정에 포함하지 않습니다.
요약 시작 시에도 자동으로 준비하며, 파일 목록·크기를 검사한 완료 기록이 있으면 네트워크 다운로드를 건너뜁니다.
기본 구간 다운로드의 모델과 미완료 구간은 `models/embedding/<revision>/`에, 완료 기록은 `models/embedding-ready.json`에 저장합니다(모두 배포 ZIP 제외). 기존 Hugging Face 캐시에서 완료된 파일도 재사용합니다.
기존 캐시만 있고 완료 기록이 없으면 최초 한 번 원격 파일 목록을 확인하며, 캐시 파일은 재사용합니다.
다운로드 완료와 메모리 로딩은 별도 단계입니다. 완료된 파일은 `local_files_only=True`로 로딩합니다.

1. 매 작업마다 국가법령정보센터 시행일 기준 현행법령 API(`target=eflaw`, `nw=3`)로 직제 시행규칙을 조회합니다. 시행 예정·연혁 자료로 대체하지 않습니다.
2. 조·항·호에서 부서명과 분장업무를 추출합니다. 과장·담당관뿐 아니라 센터장·분원장·지소장·관리소장 등의 표현과 같은 조문 내 다른 항·호를 인용하는 업무를 처리합니다. 인용한 업무와 적용 범위는 함께 보존하며, 동일 명칭 부서는 기관·조문으로 구분합니다.
3. `dragonkue/snowflake-arctic-embed-l-v2.0-ko`로 주요내용 항목과 분장업무를 임베딩합니다. 정규화 벡터의 코사인 유사도 **0.7 이상(포함)**인 부서만 후보로 사용합니다. 여러 요약 항목·업무 조각 중 최대 유사도를 부서 점수로 사용하며, 입력이 길면 잘라 버리지 않고 분할하여 모두 비교합니다.
4. GPT에 법령 주요내용과 기준을 통과한 후보의 전체 분장업무를 보내 가장 관련성이 높은 부서 하나를 선택합니다. 비고에는 기관명 접두어 없이 **지원과** 같은 실제 부서명을 출력합니다(담당관·센터 등도 법령상 명칭 유지). 후보가 없거나 GPT가 직접 관련성이 없다고 판단하면 **없음**입니다. 조회·추출·모델·응답 오류는 비고를 빈칸으로 두고 화면 오류 목록과 처리기록에 사유를 남깁니다.
5. 처리기록에 법령 시행일·조회시각·본문 해시, 후보 점수·근거 조문·선택 결과를 저장합니다.

파서 재현 검증은 `python tools/check_department_parsing.py`로 공개된 2026-08-28 시행 본문의 문단을 API 형태로 변환해 수행할 수 있습니다. 이 고정 본문은 검증용이며 실제 추천에서는 매번 공동활용 API의 현행법령 응답을 사용합니다.
실제 API의 항 번호는 16항부터 `⑯` 대신 `<16>` 형태일 수 있으며 두 표기를 모두 처리합니다. `python tools/check_department_parsing.py --api`는 공식 API 안내의 공개 샘플 OC(`test`)로 현행 XML을 직접 검증합니다. 공개 샘플의 접근 권한은 운영 인증을 대신하지 않으며, 웹에서는 본인의 승인된 OC를 입력해야 합니다.

### 이미 만든 요약의 빈 비고만 채우기

임베딩 없는 비교 실험은 결과 화면의 **실험 · 임베딩 없이 GPT로 첫 두 행 추천**에서 실행합니다. API 키·OC와 전송 동의를 입력한 뒤 **GPT만으로 두 행 실험**을 누르세요. 기존 비고가 `없음`이어도 첫 두 행을 다시 검토합니다. 전체 부서 업무분장을 GPT에 보내 부서와 근거 업무·이유를 받고, 관련 부서가 없으면 `없음`을 허용합니다. 임베딩 모델과 threshold를 사용하지 않으며 기존 엑셀은 변경하지 않습니다. 실험 결과는 화면과 별도 JSON 기록으로 제공합니다.

1. `python start_web.py`로 웹을 다시 실행합니다.
2. 첫 화면에서 **기존 요약 결과 불러오기 · 빈 비고만 채우기**를 펼쳐 해당 실행 결과를 선택하고 **기존 결과 불러오기**를 누릅니다.
3. 결과 화면의 **빈 비고만 채우기**에서 OpenAI API 키와 국가법령정보센터 OC를 입력하고 전송 동의 후 **빈 비고 채우기**를 누릅니다.
4. 완료 후 새 엑셀을 다운로드합니다. 기존 파일은 덮어쓰지 않습니다.

법령명·주요내용·소관기관·제출기한과 이미 채워진 비고는 유지하며, 빈 비고만 현행 업무분장으로 재처리합니다. 문서 요약 API는 다시 호출하지 않지만 부서 선정 API 비용은 발생할 수 있습니다. 초기화에 실패하면 기존 결과를 유지하고 오류를 표시합니다. 기준 미달은 `없음`, 실행 실패는 빈칸과 오류 사유로 구분합니다.

임베딩은 PyTorch에서 CUDA를 사용할 수 있으면 NVIDIA GPU, 아니면 CPU를 자동 선택합니다. 임베딩 생성과 코사인 유사도 행렬 계산 모두 같은 장치에서 수행하고 최종 점수만 CPU로 가져옵니다. 실제 사용 장치는 진행 화면과 처리기록에 남습니다. GPU가 있어도 CPU 전용 PyTorch라면 CPU를 사용합니다.

이 PC의 RTX 4060 / CUDA 12.6 대응 드라이버에서 GPU용 패키지를 설치하는 명령은 다음과 같습니다. 다른 PC에서는 해당 GPU·드라이버에 맞는 PyTorch 패키지를 선택하세요. 설치 후 웹앱을 재시작해야 합니다.

```powershell
.\.venv\Scripts\python.exe -m pip install "torch==2.14.0+cu126" --index-url https://download.pytorch.org/whl/cu126
.\.venv\Scripts\python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available())"
```

GPU는 다운로드를 가속하지 않습니다. 이 임베딩 모델의 가중치는 약 2.27GB이며 다운로드 속도는 네트워크·저장 서버·디스크 등의 영향을 받습니다. 속도가 느려도 기존 캐시와 미완료 파일은 삭제하지 마세요.
모델 파일은 기본 8개 작업으로 병렬 다운로드합니다. 사내 프록시나 느린 디스크 환경에서는 웹앱 실행 전에 `$env:EMBED_DOWNLOAD_WORKERS=4`처럼 1~32 범위로 조절할 수 있습니다.
`start_web.py`는 기본적으로 가중치를 1MB 구간으로 병렬 다운로드합니다. 각 요청은 시간 제한과 최대 5번의 시도를 가지며, 완료 구간은 서버 재시작 후에도 재사용합니다. 최종 파일은 원본 SHA-256과 일치한 경우에만 사용합니다. 조립 시 구간 파일과 최종 파일이 함께 존재하므로 모델 크기의 약 두 배 여유 공간이 필요합니다. 성공 후 구간 파일은 정리합니다.
Xet을 직접 사용하려면 `python start_web.py --xet`, Hugging Face 기본 HTTP를 쓰려면 `python start_web.py --http`로 실행하세요. 방식 변경에는 서버 재시작이 필요합니다. 설치된 Hub 1.32에서는 기본 HTTP의 미완료 임시 파일이 프로세스 간에 재사용되지 않습니다. 구간 다운로드와 Xet/기본 HTTP 간 부분 파일도 호환되지 않습니다. 완료된 캐시는 유지하세요.
웹 없이 준비와 로컬 임베딩 검증을 실행하려면 `.\.venv\Scripts\python.exe tools/prepare_embedding.py --verify`를 사용하세요. `--seconds 180`을 추가하면 제한 시간 뒤 중단하고 완료 구간을 보존합니다. DNS 실패·서버 연결 끊김 같은 네트워크 문제는 코드만으로 회선 속도를 보장할 수 없습니다.
최초 사용 시 Hugging Face 모델 다운로드와 충분한 디스크·메모리가 필요합니다. 모델 가중치는 ZIP에 포함하지 않습니다. 코사인 유사도 0.7은 정확도 70%를 뜻하지 않으며 실제 업무자료로 기준을 평가해야 합니다. 법령에 적힌 분장만 사용하므로 별도의 내부 업무분장까지 보장하지 않습니다.

공식 참고: [시행일 기준 법령 API](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdInfoGuide), [임베딩 모델 사용 안내](https://huggingface.co/dragonkue/snowflake-arctic-embed-l-v2.0-ko).

## 폴더 구성

- `app.py`, `start_web.py`: 화면과 실행 진입점
- `webapp/`: API 요청, ZIP·공문 처리, 정렬 및 작업 실행
- `lawtool.py`, `windows_runtime.py`: 문서·엑셀 공통 처리와 기존 호환 보조 코드
- `assets/`: 화면 스타일과 로고 안내
- `tools/`: HWP 변환기 소스·빌드와 소스 ZIP 생성
- `tests/`: 자동 검증
- `config.json`, `requirements-web.txt`: 변환기 경로 등 설정과 웹앱 의존성
- `output/`: 실행 결과 저장(자동 생성, GitHub 제외)
- `.venv/`: 이 PC의 실행환경(GitHub 제외)

ZIP을 풀어서 내부 파일을 저장소에 올리세요. 원본 업무문서, 결과물, 가상환경, 모델, API 키, 빌드된 JAR는 포함하지 않습니다.

## 입력

- 권장: 요청공문 PDF와 법안 HWP/HWPX를 함께 넣은 의견조회별 ZIP.
- 여러 의견조회 ZIP을 하나로 묶은 통합 ZIP, 내부 첨부 ZIP 지원.
- 원래 폴더 관계를 유지하세요. 연결이 불명확하면 검토 오류로 처리합니다.
- 결과 화면·엑셀·처리기록의 성공 문서는 원본 ZIP/폴더/파일명의 자연 정렬 순서(2 → 10, 10-1 → 10-2)를 따릅니다. 업로드 선택 순서나 ZIP 내부 저장 순서와 무관하며, 실패 문서는 건너뜁니다. 한 문서의 여러 법령은 원문 등장 순서를 유지합니다.
- PDF는 텍스트 기반 요청공문과 입법·행정예고 보조자료를 지원합니다. 스캔 PDF, 그 밖의 PDF 법안, 암호·DRM 문서는 지원하지 않습니다.
- 업로드 합계 100MB, 압축 해제 누적 250MB, 최대 중첩 8단계 및 방문 항목 1,000개.
- 법안 단독 입력 시 공문에서 추출하는 기관·부서·기한은 빈칸입니다.

## 결과

법령명은 `1. 공무원 임용규칙`처럼 원본 묶음 번호와 법령명으로 표시하며 의원명은 표시하지 않습니다. 의원명은 법안 구분과 처리기록에만 보존합니다. 날짜로 시작하는 통합 ZIP명은 번호로 사용하지 않으며, 번호를 찾지 못하면 임의로 생성하지 않습니다.
기관·부서는 공백으로 연결하고, 제출기한은 `2026.9.23(수)`로 표시합니다. 원문에 시간이 있으면 뒤에 보존합니다.
비고(소관부서)는 추천 결과를 표시합니다. 자동 판정이므로 원문과 업무분장을 검토하세요.
변경점 중심 요약 한 가지 방식으로 실행합니다.
결과와 추출 이력은 `output/`에 저장됩니다. 원문 대조 검토 후 사용하세요.

## 보안·제약

문서 전체에서 추출한 텍스트가 OpenAI API로 전송됩니다. 외부 전송이 허용된 자료만 사용하세요.
