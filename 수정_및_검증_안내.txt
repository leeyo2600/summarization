- 두 프로그램의 API 키 입력칸에 "API 키를 입력해주세요" 안내 문구를 표시합니다.
- law_go의 "입력 후 실행" 문구를 제거했습니다.
- law_summary의 상자, 입력칸, 파일 업로드 영역과 버튼 디자인을 law_go 기준으로 맞췄습니다.

적용 내용
- law_go: AI 제공자/비즈라우터 선택과 모델 설정 화면을 제거했습니다.
- law_summary: AI 서비스 선택/비즈라우터 선택을 제거했습니다.
- 두 프로그램의 화면에서는 OpenAI API 키만 입력합니다.
- 국가법령정보센터 OC 표시를 "국가법령정보 API 키"로 바꿨습니다.
- 요청한 승인 OC 입력 안내와 사용자 ID 설명을 제거했습니다.
- 마지막으로 입력한 OpenAI 키와 국가법령정보 API 키를 자동 저장하고 재실행 때 복원합니다.
- 입력값을 수정하면 저장값도 갱신하고, 지우면 저장값도 지웁니다.
- 키는 .local/credentials.json에 Windows 현재 사용자 DPAPI로 암호화합니다.
  같은 PC, 같은 Windows 계정에서 복원합니다. 다른 PC/계정에서는 다시 입력하세요.
- 작업 시작 후에도 키를 유지합니다. 기존 법령 처리 알고리즘과 기본 모델은 유지했습니다.

사용 방법
1. 각 ZIP 전체를 새 폴더에 압축 해제합니다.
2. law_go는 LAWGO_RUN.cmd, law_summary는 law_summary.cmd를 실행합니다.
3. 첫 실행에 두 키를 입력하고 입력란 아래 저장 완료 상태를 확인합니다.
4. 이후 같은 폴더의 프로그램을 다시 열면 저장된 값이 채워집니다.
law_go는 원본과 같이 PC에 설치된 Python 3.12 또는 3.13을 사용합니다.
law_summary는 원본에 포함된 Python/Java 실행환경을 유지했습니다.

검증 결과와 범위
- law_go 관련 테스트 40개 통과, JavaScript 구문 검사 통과.
- law_go 전체 테스트 139개 중 138개 통과. 나머지 1개는 기존 HTTPS 전송 테스트
  test_missing_truststore_uses_verified_requests_default의 실패입니다.
  해당 테스트와 http_transport.py는 원본 ZIP과 바이트가 동일함을 확인했습니다.
- law_summary 관련 테스트 7개, 내장 실행환경 점검, JavaScript 구문 검사 통과.
- 공유 저장 모듈 테스트 7개 통과, 실제 DPAPI 재시작 검사는 환경 제한으로 1개 건너뜀.
- 브라우저에서 두 화면을 확인하고 테스트 키의 저장/갱신/새로고침 복원을 점검했습니다.
  law_go는 테스트 서버 재시작 뒤 OpenAI 테스트 키 복원도 확인했습니다.
- 현재 실행 샌드박스는 실제 사용자와 Windows 계정이 달라 DPAPI에 접근하지 못합니다.
  저장 및 화면 검사는 테스트 전용 대체 암호화 함수로 수행했습니다.
  배포 프로그램에는 대체 함수나 평문 저장 기능을 포함하지 않았습니다.
  실제 사용자 Windows 계정에서의 암호화 저장 및 실제 API 요청은 검증하지 않았습니다.
- 실제 API 키, 테스트 저장 파일, 실행 로그는 배포 ZIP에 포함하지 않았습니다.
